# Mosaic Desktop 功能、设计与交互评审

评审日期：2026-10-24。对象：当前工作区 v0.7 开发预览，包含评审开始前已有的未提交修改。

## 后续落实说明 · V0.8／V0.8.1

本文保留评审发生时的观察与建议，以下正文不是当前缺陷清单。V0.8 后续已实现设置抽屉焦点隔离、桌面内容保存状态与失败重试、资源详情手动收起、组件只读预览、待办编辑／撤销删除、布局吸附与键盘微调、工作空间独立桌面布局，以及主题与快捷键设置。V0.8.1 进一步调整了顶部菜单工作区占位。

当前操作、硬件数据来源与验证范围见 [V0.8／V0.8.1 指南](EXPERIENCE_V0.8.md)。这些落实不代表本文全部建议已经完成；内置音量滑块、更多资源重定位操作、多屏设备和长期稳定性等仍需后续实现或验证。

## 结论

Mosaic 已经具备桌面工具的主要功能：桌面组件、Dock、系统状态、搜索、资源库和工作空间。下一轮的最大收益是改善可理解性、操作反馈和视觉层级。现有深色蓝灰配色可以保留，主要问题是小字号、重复说明、管理表单过多，以及实际桌面与旧 Dashboard 概念混用。

建议先修复确定的交互问题，再做视觉统一，最后扩展场景功能。以下优先级为此次评审建议，并非已经确认的开发排期。

## 应先解决的交互问题

### P1：设置抽屉没有隔离键盘焦点【实测】

复现：打开工作空间页，点击左下角设置，再按 Tab。焦点进入遮罩后面的“工作空间名称”输入框，而不是设置抽屉内部。用户可能在看不清内容时编辑底层页面。

原因：抽屉只改变 Visibility，没有移动并约束焦点，也没有禁用底层内容。

建议：打开时保存原焦点，将焦点移到抽屉；在抽屉内循环 Tab，禁止底层接受键盘操作；关闭后恢复触发按钮焦点。若保留显式保存，关闭时应明确处理未保存更改。

代码：`src/Mosaic.Host/Views/DashboardWindow.xaml:78`；`src/Mosaic.Host/Views/DashboardWindow.xaml.cs:149`、`:216`。

验收：Tab / Shift+Tab 不会穿出抽屉；Escape 关闭后焦点回到入口；遮罩后的输入框不会被编辑。

### P1：桌面笔记、待办缺少就地保存失败反馈【源码确认，未注入失败】

笔记与待办自动保存异常只写入 DashboardViewModel.Status。桌面组件模板未绑定该状态，DesktopSurface 的错误文字只处理布局保存。用户关闭设置中心后，可能不知道桌面内容仍未保存。

建议：在笔记/待办组件底部提供“保存中 / 已保存 / 保存失败，重试”；失败状态保持可见，保留未保存内容，并提供复制内容或重试入口。不要让无关的系统采样状态覆盖保存错误。

代码：`src/Mosaic.Host/ViewModels/DashboardViewModel.cs:87`、`:128`；`src/Mosaic.Host/Themes/WidgetTemplates.xaml`；`src/Mosaic.Host/Views/DesktopSurface.cs:47`。

验收：模拟文件冲突或写入失败，关闭主窗口后桌面组件仍能显示失败状态并恢复保存。

### P2：宽窗口下“详情”按钮无法收起资源侧栏【实测】

1280 宽窗口点击“详情”两次，面板始终显示。原因是 `ActualWidth >= 1000 || _details` 强制宽窗口展开，覆盖了用户操作。

建议：将“按窗口宽度决定初始状态”和“用户手动选择”分开。按钮显示选中态或“收起详情”，无资源选中时不展示整列禁用操作。

代码：`src/Mosaic.Host/Views/LibraryView.xaml.cs:92`—`:99`。

验收：宽、窄窗口均可展开和收起；调整窗口宽度不覆盖明确的手动选择。

### P2：桌面未启用时，主操作仍是“编辑桌面布局”【实测】

首次启动主区域突出“编辑桌面布局”，点击后只有底部小字“请先启用 Mosaic 桌面。”。右上方才是真正的启用入口。选中组件也不表示组件已经出现在桌面。

建议：未启用状态在主区域显示“启用并编辑桌面”，旁边说明将隐藏系统任务栏与桌面图标，并显示返回 Windows 的快捷键。组件卡片区分“已选择，启用后显示”和“正在桌面显示”。

代码：`src/Mosaic.Host/Views/DashboardWindow.xaml:61`；`src/Mosaic.Host/App.xaml.cs` 中 `desktop.edit` 命令。

### P2：工作空间中的“布局”概念与当前桌面不一致【源码确认 + 界面观察】

界面介绍独立 Dashboard 布局，并显示“8 个 Dashboard 组件”。当前主入口展示的是插件管理；实际桌面位置保存在全局 AppSettings.Desktop.Widgets，工作空间切换不切换这些位置。Writing 预设调整的也是旧 Dashboard 布局。

这是产品概念和可发现性问题，不代表切换持久化本身损坏。

建议近期明确写“切换 Dock 与资源；桌面组件位置、笔记和待办共用”，隐藏用户无法通过正常主导航编辑的 Dashboard 数量。下一版再让工作空间可选择保存桌面组件的启用状态与位置。

代码：`src/Mosaic.Core/Models/Documents.cs:83`；`src/Mosaic.Host/Services/WorkspaceManager.cs:128`；`src/Mosaic.Host/Views/WorkspacesView.xaml:7`；`src/Mosaic.Host/Views/DashboardWindow.xaml.cs:171`。

### P2：小窗口下，工作空间的主要操作被说明文字挤走【实测】

约 724×565 时，右侧面板首先显示名称、计数和长说明，切换按钮落到滚动区域下面。主操作应该比规则说明更容易找到。

建议把切换按钮固定在所选工作空间标题旁或面板底部；长说明折叠到“切换包含哪些内容”；窄窗口用列表与详情切换，避免两列同时挤压。

代码：`src/Mosaic.Host/Views/WorkspacesView.xaml:7`。

## 视觉设计建议

| 区域 | 当前观察 | 建议 |
| --- | --- | --- |
| 字体 | 导航 10 DIP，大量辅助文字 9–11 DIP，标题栏时间仅 8 DIP；大屏有留白但正文仍很小 | 正文建议 14 DIP、辅助文字 12 DIP、标题 24–28 DIP；另提供紧凑密度，避免所有文字一起缩小 |
| 组件管理 | 八张卡片都是复选框加同一句说明，无法看出实际效果 | 改称“桌面组件”；每张卡片展示真实比例缩略预览、用途、启用状态；提供小/中/大尺寸选项 |
| 配色 | 整体蓝灰已统一，但大量硬编码颜色、深浅层级相近 | 保留蓝灰；统一背景/面板/浮层、主文/辅助文、边框/选中态等语义资源，主按钮只保留一个明显强调 |
| 原生控件 | 自定义圆角按钮与白色默认复选框、滑块混在一起 | 统一复选框、开关、滑块、滚动条和焦点样式；先保证清晰与状态一致，再考虑材质效果 |
| 插件页空间 | 上半区有重复卡片，下半区大面积空白 | 用两到三列带预览的组件卡，或左侧组件列表、右侧桌面预览；让留白承载预览与状态 |
| 资源库 | 空列表时也显示整列禁用按钮，页面底部还有两层状态文字 | 空状态提供“添加文件 / 添加文件夹”；选中资源后才显示详情；批量操作用上下文工具条 |
| 搜索 | 应用结果使用同类文件字形；默认详情面板展示路径与很多整理操作 | 应用使用真实图标；优先名称、来源和匹配词；默认突出结果，Tab/操作入口再展开详情；已有方向键/Enter 交互应保留 |
| 用语 | 插件/组件、工作台/Dashboard/设置中心、Command Palette 混用 | 统一成“桌面组件、设置中心、全局搜索、资源库、工作空间”；“JSON 配置目录”等放进高级设置 |

颜色和字号是设计建议，未声称现有界面经过完整无障碍标准审计。可增加跟随系统的浅/深色主题；当前模型验证仅接受 Dark，需要同步调整模型和资源，不宜只替换几个色值。

## 功能增强：按实际收益排序

1. **完成日常编辑闭环。** 待办支持编辑标题、删除后撤销、折叠已完成；目前“今日待办”没有日期模型，可先改称“待办”。笔记补就地保存反馈。用户每天都会遇到这些细节。
2. **桌面布局更容易整理。** 增加网格吸附、对齐参考线、恢复默认、键盘微调与撤销。现有桌面控件可自由移动/缩放，但统一最小尺寸 160×100，没有按内容约束；先给时钟、待办等不同最小尺寸和紧凑模板，再扩大自由缩放范围。
3. **减少设置试错。** Dock 大小、组件尺寸、透明度提供即时预览与取消恢复；当前 Dock 大小需保存后应用。桌面启用、自动隐藏、启动行为分组，不让用户在长复选框列表中找功能。
4. **改善资源整理效率。** 支持文件拖入登记、Enter 打开、F2 重命名显示名称、常用右键动作、标签 chips，以及失效路径的重新定位。不要把原文件操作和仅移除登记混在一起。
5. **让系统状态承担快速操作。** 顶栏音量目前打开 Windows 声音设置，可增加本地音量滑块/静音；网络保留状态和设置入口。保留原系统深层设置入口。
6. **增强工作空间差异。** 提供预览和明确切换范围，支持归档/删除自建工作空间；再实现独立桌面组件布局。AI Lab/Writing 在当前可见桌面上的区别不够明显，不宜靠名称暗示尚未实现的专属能力。

多屏混合 DPI、Explorer 重启、休眠唤醒、全屏应用和长期驻留属于桌面替代软件的关键验证项，应在推广使用前完成专项实机验收。本次没有证据判定这些场景已经发生故障。

## 建议实施顺序与验收

**第一轮：可靠反馈与操作一致性。** 修复抽屉焦点、详情切换、编辑入口和保存失败提示；明确工作空间范围。验收以键盘操作和真实失败路径为主。

**第二轮：统一视觉与页面布局。** 建立字体、间距、颜色与组件样式资源；改版组件管理、资源库空状态、搜索结果和设置分组。覆盖默认、空、选中、错误及窄窗口状态，不只验收漂亮的默认截图。

**第三轮：日常效率与场景能力。** 待办撤销/编辑、布局吸附、即时预览、工作空间独立布局，以及系统快速操作。每项增加前明确它解决的日常操作成本。

附带的交互示意用于比较“组件卡片”和“桌面预览”两种管理方式；其中内容为示例，开关只影响示意，不会改变真实 Windows 或 Mosaic 配置。
