# 桌面控件实现复核 · V0.6.1

本次按用户要求重新审查“固定在桌面的控件”，并替换 V0.5 的实现。

## V0.6.1：用户反馈“显示桌面”后没有控件

V0.6.0 的检查证明了子窗口存在、布局尺寸和应用遮挡关系，但没有证明控件最终出现在桌面上。用户反馈说明此前不能据此宣布桌面可见性验收完成。

检查发现 `DesktopOverlay` 隐藏了整个 `SHELLDLL_DefView`，同时把控件画布放在它的父窗口上。当前 Windows 11 的 Progman 使用独立合成层；旁边还有一个全屏但禁用输入的壁纸 WorkerW，不能作为交互控件宿主。

V0.6.1 保留 `SHELLDLL_DefView` 可见，只隐藏其中的 `SysListView32/FolderView` 图标列表；把画布作为这个可见桌面内容层的子控件。检查补充了宿主类名、可见性、启用状态、图标列表恢复、实际布局尺寸以及键盘焦点和字符输入。画布原生窗口意外隐藏后会重新显示。

这些检查覆盖原生结构和输入链路。V0.6.1 启动后，用户已明确反馈“能看到了”，确认按 Win+D 返回桌面后能够看到控件。这是用户在当前机器上的实机确认，不扩大为所有 Windows 版本、多屏或 Explorer 重启场景的验收。

## 发现与修正

| 问题 | 复核结果 | 修正 |
| --- | --- | --- |
| 插件实际是浮窗 | `DesktopPluginWindow : Window` 仅设置工具窗口样式，没有桌面父窗口；隐藏任务栏条目并不能让它成为桌面控件。 | 删除独立插件窗口。一个 `DesktopSurface` 原生子窗口挂在 Explorer 的 `SHELLDLL_DefView` 内，内部全部使用 `DesktopWidget : UserControl`。 |
| 日常使用也能移动和缩放 | 标题栏直接 `DragMove()`，边框允许缩放，持续显示关闭按钮。 | 普通状态锁定，无窗口标题栏、关闭按钮、缩放边框和阴影。仅“编辑桌面布局”显示移动/缩放手柄；完成保存，取消恢复，Escape 取消。 |
| 内容模板依赖顶层窗口 | 通过 `AncestorType=Window` 获取笔记、待办、时钟和快捷访问，无法直接复用于真正的桌面子控件。 | 使用可继承的 `WidgetContext.Owner`，桌面与设置中心继续共用一个内容模型。 |
| 退出编辑可能丢失布局 | 插件开关、设置保存或工作空间切换可能销毁/刷新控件。 | 在上述操作和退出前提交桌面布局；保存期间禁止继续拖动；失败保留编辑状态并显示错误。 |
| 管理窗口仍可能回到旧工作台 | 关闭资源库/工作空间模块时会跳回旧 Dashboard。 | 回到插件管理页，管理窗口继续承担设置、资源和插件开关。删除未使用的旧时钟浮窗代码。 |

## 层级约定

- 壁纸和桌面宿主 → 桌面控件画布 → 普通应用窗口。
- Dock、顶部菜单栏各自保留边缘唤出和置顶逻辑，不用于承载桌面插件。
- 桌面画布为 `WS_CHILD`，没有 `WS_POPUP` 或置顶样式，不产生独立 Alt+Tab 插件窗口。
- 在创建子窗口前匹配桌面宿主 DPI 上下文；通过 `HwndSourceParameters.ParentWindow` 直接创建子窗口，不先建立顶层窗口再调用 `SetParent`。
- 透明部分保留壁纸，画布内只有控件区域参与交互。找不到桌面宿主时不创建浮窗替代；定时检查宿主有效性，必要时重新建立子窗口。

实现参考：[Win32 子窗口](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#child-windows)、[SetParent 的样式和 DPI 限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)、[WPF 透明子窗口的源码说明](https://source.dot.net/PresentationCore/System/Windows/InterOp/HwndSourceParameters.cs.html)。使用 `UsesPerPixelTransparency`，不使用只适用于顶层窗口的旧 `UsesPerPixelOpacity` 参数。

## 验证范围

Release 构建 0 警告、0 错误；完整自动检查 28/28 通过。Windows 原生窗口复核覆盖：

- 原生父窗口确为 Explorer 桌面宿主，画布有 `WS_CHILD`、没有置顶标记，顶层窗口中没有插件窗口。
- 真实最大化测试应用覆盖桌面控件；鼠标命中属于应用窗口。应用工作区与屏幕工作区一致，Dock 保持置顶。
- 默认锁定状态不响应布局拖动；编辑后位置与尺寸保存；取消恢复原布局；重建桌面后仍为锁定状态。
- 笔记模板实际挂在透明桌面子窗口下，可获得键盘焦点并处理原生字符消息；内容写入共享模型，关闭管理窗口后继续保存。该检查不替代输入法组合输入的实机验证。
- 顶部菜单完全隐藏、展开、菜单打开期间保持显示；正常退出和强制终止后恢复 Windows 任务栏、工作区和自动隐藏设置。

本机是 Windows 11、主屏 150% 缩放。控件画布当前覆盖主屏；多屏控件布置、真实 Explorer 重启、输入法组合输入、虚拟桌面切换和长时间驻留仍需实机扩展验收。宿主恢复代码已经实现，但不将其等同于上述场景全部通过验收。
